# School Procurement Ledger

Прототип системы прозрачного учёта закупки компьютерного оборудования для школ. Сервис фиксирует этапы `TenderCreated → BatchRegistered → ScannedAtSchool → Accepted → PaymentReleased` в SQLite и связывает события SHA-256 цепочкой. API и интерактивная документация доступны через FastAPI.

## Запуск

Требуется Python 3.11 или новее.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000/docs`. База `procurement.db` создаётся автоматически; путь можно изменить переменной `LEDGER_DB`.

## Демонстрационный сценарий

1. `POST /tenders`: создайте закупку с названием, школой, количеством, спецификациями и бюджетом.
2. `POST /tenders/{id}/batches`: зарегистрируйте поставщика и массив уникальных `device_ids` (по одному на устройство).
3. На каждый ID вызовите `POST /tenders/{id}/scans` с отпечатком SHA-256 из локального агента. Повторное сканирование устройства блокируется.
4. `POST /tenders/{id}/accept`: приёмка доступна, когда каждое устройство партии отсканировано и нет высокого риска.
5. `POST /tenders/{id}/release-payment`: запишите демонстрационное событие выплаты после приёмки.
6. `GET /tenders/{id}/events` покажет журнал, а `GET /ledger/verify` проверит целостность его хэш-цепочки.

Пример создания закупки:

```json
{
  "title": "Компьютеры для школы №15",
  "school": "Школа №15, Караганда",
  "quantity": 1,
  "specifications": {"cpu": "Core i5", "ram_gb": 16, "ssd_gb": 512},
  "budget": 500000
}
```

Запуск агента (используйте ID тендера из ответа API и один `device_id` из партии):

```powershell
$env:AGENT_HMAC_KEY = "секретный ключ, общий для проекта"
python -m agent.collector --tender <ID> --device SCHOOL15-PC-001
```

## Границы прототипа

- Это централизованный журнал с проверяемой цепочкой хэшей, а не сеть Hyperledger Fabric: администратор SQLite может переписать базу и пересчитать цепочку.
- ЭЦП НУЦ РК, Госзакупки, RFID/QR сканеры, GPS и цифровой тенге не подключены. `PaymentReleased` только фиксирует событие и не переводит деньги.
- `app.risk` — прозрачные эвристики, а не обученная ML-модель. Результат служит сигналом для проверки человеком, не доказательством нарушения.
- Агент не считывает CPU ID, серийные номера, MAC или геопозицию. Он формирует HMAC-псевдоним из ограниченного профиля ОС/архитектуры; это не аттестация подлинности устройства и не заменяет осмотр и сверку спецификации.
- Для реального внедрения нужны аутентификация и роли, защищённое хранение ключей, журналирование доступа, шифрование, политика хранения данных, аудит модели и подключение разрешённой сети/провайдера платежей.
